Nuthatch 3.8.5 fixes two correctness faults in the analytics surface.

## Compatibility and upgrade

Replace the binary and restart. There is no storage migration, configuration change, NID change or
re-index required. Existing sealed segments remain readable.

## Scaled decimals are safe in `/sql` (#1433)

`/sql` could panic when DuckDB returned a scaled `DECIMAL` whose unscaled value did not fit
`rust_decimal`'s 96-bit representation. This was most likely for token quantities expressed with
many decimal places. The query now detects scaled decimal result columns and re-executes the result
projection as strings, preserving the exact decimal value rather than narrowing it through the
driver. Ordinary query results and unscaled decimals are unchanged.

The compatibility path accepts statements ending in a semicolon, including a final line comment.

## Sealed velocity seeds use integer division (#1432)

The cold-store velocity path used `/` where it needed integer division when deriving the start of a
sealed segment window. DuckDB treated the result as a floating-point value, so valid sealed velocity
seeds could be skipped silently. The calculation now uses `//`, matching the hot-store path and
including the expected sealed windows in velocity results.
