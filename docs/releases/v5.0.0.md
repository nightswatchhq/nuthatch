Nuthatch 5.0.0 is a smaller nuthatch. It removes the WASM transform layer and live screening, builds
the shipped binaries with fat LTO, and drops a second copy of the Arrow libraries. It is 4.15.2 plus
that removal. It is a major release because two of the removals break the 4.x stability contract;
nothing a known nest uses is among them.

## What breaks

The WASM layer is gone: `nuthatch transform`, `nuthatch screen`, `nuthatch audit replay`, the live
screener, the `wit/` interfaces and the components, and with them wasmtime (#2001). No production nest
used any of it, and the transform layer was never in the indexing path.

- **A `nuthatch.toml` with a `[screening]` table no longer loads.** The error names the table and says
  it was removed. Delete the table to load the nest; nothing else in it changes meaning. `doctor` still
  reads past it.
- **The `screen_status` MCP tool is gone.** A nest only advertised it when screening was configured.
- A compliance pack manifest with `screening` or `components` entries is now refused at `pack verify`
  rather than passing with those claims ignored.

Labels, lists, flags, exposure, velocity, `audit report` (threshold flags) and `audit sealed` are
unchanged. Neither break had the deprecation window the contract describes; Chief chose the major
version over carrying an unused surface through one.

## Smaller and faster to build

- **Fat LTO for shipped binaries.** Release binaries are built with a new `dist` profile (`lto = "fat"`,
  `codegen-units = 1`). On macOS the binary went from 158.9 MB to 106.7 MB before the WASM removal was
  counted (#2004). CI's gates still measure the thin `release` profile, which is the larger binary.
- **Without wasmtime:** 100 fewer crates in the dependency tree (797 to 697) and 19.5 MB less binary
  under the thin profile (164.0 to 144.5 MB, macOS).
- **Arrow and Parquet 59.** nuthatch pinned the 58 line while Burrmill and DataFusion bring 59, so the
  binary carried both. The lock loses 17 packages (#2004).
- The Graph query modules compile only in a `graph` build, which is where they were ever used (#2002).
- The `exex` cargo feature is gone. It was a stub; ExEx ingestion remains designed, not built (#2000).

## New segments hash differently

Parquet 59 writes a different `created_by` stamp, so a segment sealed by 5.0.0 has a different content
hash from the same rows sealed by 4.15. Existing segments are read and never rewritten, nothing needs
re-indexing, and decoded rows are identical. The stability contract already leaves segment identity
across arrow-rs releases outside the promise; compare decoded rows, not hashes, across versions.

## Gated on Lodestar's data

The release gate passed on every production nest, run on the ThinkPad on 2026-10-09 against a Linux
`dist` build of commit c1905ea9. The commits after it on the release branch change only these notes,
so the tagged code is the code gated. Each nest ran against the version it runs in production:

| nest | answered | answers differ | p99 (5.0.0 / baseline) | peak RSS (5.0.0 / baseline) |
|---|---|---|---|---|
| allocations | 75 of 75 | 0 | 2,394 / 2,572 ms | 1,873 / 1,910 MiB |
| QoS | 9 of 9 | 0 | 2,386 / 2,402 ms | 1,177 / 1,209 MiB |
| GNS | 9 of 9 | 0 | 150 / 171 ms | 165 / 201 MiB |
| DIPs | 16 of 16 | 0 | 55 / 96 ms | 75 / 108 MiB |
| data services | 5 of 5 | 0 | 12 / 15 ms | 64 / 93 MiB |
| staking archive | 3 of 3 | 0 | 29 / 33 ms | 78 / 111 MiB |

None regressed; every peak is inside the 2,048 MiB budget. The baselines are 4.15.2, except staking
archive, which runs 4.14.0. The Linux binary is 110.6 MB against 4.15.2's 193.3 MB.

## Compatibility and upgrade

Replace the binary and restart. No re-index and no configuration change, unless a nest carries a
`[screening]` table, which must be deleted first.
