Nuthatch 3.12.2 moves the WASM runtime past two security advisories, holds a nest mounted on a
running runtime to the rules boot already enforces, finishes the 504 for a spent query budget that
3.12.1 began, and reads two GraphOps RPC responses correctly. It is a binary swap and a restart.

## Compatibility and upgrade

Replace the binary and restart. There is no storage migration, configuration change, NID change or
re-index required. Existing sealed segments remain readable. The component-model API is unchanged
across the Wasmtime bump, so existing transform components load as they are.

## Wasmtime 48.0.3 (#1554)

The transform host moves from Wasmtime 46.0.3 to 48.0.3, which fixes RUSTSEC-2026-0314 (a guest
can panic the host through the filesystem) and RUSTSEC-2026-0316 (an allocation fault in
dynamic record lifting). A component granted no capabilities never reaches the filesystem, but an
operator running effectful components should take this release.

## Live mount follows boot (#1539)

A nest brought in with `POST /_admin/nests` was not held to the same rules as one present at start.

- A mount whose acknowledgement timed out stayed on the cursor with its redb file held and no
  routes, so a retry failed with `Database already open` until a restart. The cursor now declines
  a mount the caller has stopped waiting for, and the store is released for a retry.
  An unmount that timed out no longer retires a nest whose routes are still serving (#1535).
- A mount that opens a store applies the recorded SQL surface (#1536) and takes the cursor's `/sql`
  gate (#1538).
- `seal-direct` with an authored entity is refused on a live mount as it is at boot, before
  prepare (#1537).
- `DELETE /_admin/nests/{*name}` can name a `tenant/alias` route (#1533).
- Unmount drops the analytical connection for the dataset the mount actually holds (#1531).
- A second tenant written while the mounts file is still single-tenant is persisted (#1534).

## Every spent query budget is a 504 (#1532)

3.12.1 answered a statement cut off at `SQL_TIMEOUT` with 504. Four other exits that run out of the
same budget, around a vanished segment, the integrity sweep and named-admission planning, still
answered 400 and counted as `reason="invalid"`. They now answer 504 and count under
`reason="timeout"`.

## Two GraphOps RPC responses (#1558)

GraphOps wraps an upstream `eth_call` revert as `-32603 "... 3: execution reverted"`. It was read as
a provider failure; it is now a revert, and only when the embedded upstream code is `3`, so a
wrapped provider fault is still a failure. Its `eth_getLogs` range cap, `-32012 "getLogs request
exceeded max allowed range"`, was retried at the same width; it now narrows the window. A nest
pointed at GraphOps no longer needs `--window` set by hand.
