Nuthatch 4.1.2 moves the Burrmill pin from `3e7b9f5` to `ce875bc`, for one fix: a budgeted
multi-thread sort over text columns spills instead of refusing. Take it if a nest answers
`Out of Memory Error: Additional allocation failed for ExternalSorterMerge` on a query that used to
finish.

## Compatibility and upgrade

Replace the binary and restart. There is no storage migration, configuration change, NID change or
re-index. Nothing else in nuthatch changed.

## What it fixes (burrmill b8c7114)

A string view keeps the buffer its bytes live in, and a sort's merge of spilled runs emits rows whose
views point into every read chunk they came from. DataFusion 55's `SortPreservingMergeExec` charged
each input batch for all of those chunks, so a two-thread `ORDER BY` over 42-byte addresses could cost
15 MB per 128 rows in the pool and refuse under its budget, where the same sort over `Utf8` spilled
and finished. Burrmill now compacts the view columns of every input to that merge first, so the pool
is charged for what the rows hold.

Seen in production on 2026-10-03: from about 07:00 UTC the alloc nest refused Lodestar's indexer,
network-stats, epochs, GRT-flow and POI reads, and kittiwake's `snapshot-network`, `refresh` and
`warm-ipfs` jobs, with `ExternalSorterMerge` and `HashJoinInput` out-of-memory errors.

## What it does not fix

**Hash joins and final aggregates still cannot spill.** A refusal naming `HashJoinInput` is a query
whose join build side does not fit `NUTHATCH_BURRMILL_MEMORY_LIMIT` (unset, it is
`analytics.memory_limit`). This release does not change that bound. Raise it on the nest, within
`NUTHATCH_MAX_RSS`, or the refusal stands.

The rest of burrmill between the two revisions is formatting, clippy and its first CI (burrmill#35);
no behaviour change.
