Nuthatch 4.2.0 fixes the memory regression that took the Lodestar allocations nest down on
2026-10-03, closes the rest of the confirmed audit findings, and brings Burrmill's answers closer to
DuckDB's. It is a minor rather than a patch because some answers and some admin responses change,
listed first. Take it if you run 4.1.1: a budgeted session there can refuse join- and sort-heavy
views that 4.1.0 answered.

## What answers differently

- `//` over a `DECIMAL` operand divides in `DOUBLE`, as DuckDB does: `CAST(7 AS DECIMAL(10,0)) // 2`
  is 3.5, not 3. Over `HUGEINT` it stays exact.
- `%` by zero is `NULL` for that row rather than an error for the statement.
- `LIKE` no longer treats a backslash as an escape unless `ESCAPE` says so, and any single-character
  `ESCAPE` works.
- `TRY_CAST` and `CAST` of text to `DECIMAL(p,0)` or `HUGEINT` accept DuckDB's spellings (`'1e3'`,
  `'1_000'`), so a `value_dec` that read `NULL` for such a value now reads the number.
- A statement of several statements is refused rather than having only its first run.
- An `ORDER BY` expression over an output alias binds to the alias.
- An entity value of 10^38 or more is refused when the entity loads, naming the table, column and
  value, instead of failing later inside a query.
- Functions and syntax DuckDB answers and Burrmill now also answers, or refuses by name, are listed in
  burrmill #39.

## Admin API and serving

- `POST /_admin/suspend` and `/_admin/resume` need `Content-Type: application/json`, as the other
  admin POSTs already did, and `--cors` no longer applies to any `/_admin` path. A bare
  `curl -X POST` to either now gets 415.
- Mounting a suspended name with a different NID answers 409. A repeated `?wait=true` mount of the
  same name and NID answers 200. A reclaim during a mount job answers 409 naming the job. `_admin` is
  reserved as an alias and a tenant.
- A connection that has not finished its request headers in 10 seconds is closed.
- `/table` says when its answer is hot-only (`degraded`, `degraded_tables`), as `/sql` does.
- `/ready` lists authored views that failed to build as `views_failed`.
- `nuthatch_nest_health` disappears when a mount is unmounted or suspended, instead of reading 0.

## Ingestion and storage

- The sealed watermark no longer advances past a block whose checkpoint failed to store. A window
  committed with no checkpoint is counted (`nuthatch_checkpoints_missed_total`) and warned about. A
  reorg walk that cannot answer retries rather than rolling back to block 0. A `finalized` tag at or
  past the tip falls back to the depth rule.
- Checkpoints below the newest one at or below the watermark are pruned as windows commit, so the
  checkpoint table no longer grows with chain length.
- A prune killed part-way is finished by the next one.

## Operations

- `nuthatch doctor` reports old-log evidence on its own (`old_logs`), and says a deep backfill works
  only when it saw old logs served.
- `deploy-nest.sh roll` edits the `ExecStart` systemd actually runs, accepts a roll only when `/ready`
  reports the new version, and reads any `--listen` address.
- Secrets no longer reach logs or MCP tool errors: webhook URLs are reduced to scheme and host, and
  the `/sql` error scrubber matches object_store's path spelling and the runtime's shared store.

## The 4.1.1 memory regression

4.1.1 read 128 rows per batch in a budgeted session, so that an answer's size cap could see every
row. DataFusion's repartition, filter and join operators copy batches through a buffer that grows to
1 MiB and does not shrink, and the memory pool charges by buffer capacity. Each 128-row batch of
addresses, about 5 KB of text, was charged 1 MiB, and whatever held those batches, a hash join's build
side or a sort, filled a 2 GB budget on queries 4.1.0 answered. On the Lodestar allocations nest that
was `lodestar_indexer_daily` and every view built on the reward ledger.

Burrmill now compacts the string columns at the output of every operator that builds batches that
way, under a budget, so nothing downstream sees a bloated batch. Measured on a copy of that nest under
its production settings: 4.1.0 and 4.2.0 both answer `lodestar_indexer_daily` with 20,093 rows and the
reward-to-allocation join with 510,692; 4.1.1 refused both. Peak RSS on the copy was about 1.4 GB.

## Compatibility and upgrade

Replace the binary and restart. There is no storage migration, configuration change or re-index.
Callers of `/_admin/suspend` and `/_admin/resume` need the JSON content type.
