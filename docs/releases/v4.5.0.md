Nuthatch 4.5.0 adds a sampled audit of sealed history against a second endpoint, and a per-entity
gauge of the memory DBSP holds for authored incremental entities. Both are off or inert unless you
use them: a nest that sets neither flag behaves exactly as on 4.4.1.

## Sealed-history audit

Nothing on the ingest path can see an `eth_getLogs` answer that leaves a log out of the middle of a
range (#1670): the range seals as if whole. No provider has been seen to do it. The audit is the
detector RFC-0049 §10 describes: it re-fetches sampled sealed ranges from a different endpoint,
decodes them with the nest's own registry, and compares the rows with the sealed segments for those
blocks.

- `nuthatch dev --audit-rpc <url>` runs it in the background, 24 ranges of 1,000 blocks a day by
  default (`--audit-per-day`, `--audit-span`). Off when absent.
- `nuthatch audit sealed --rpc <url> --samples N --seed S` runs it once and exits 1 on any
  difference. A seed picks the same ranges over the same segments.
- A difference is a warning naming the range, the endpoint's host and the rows, and counts in
  `nuthatch_audit_mismatches_total`, beside `nuthatch_audit_ranges_total` and
  `nuthatch_audit_errors_total`. Sealed data is never touched.
- An endpoint the nest indexes from, primary or fallback, is refused: it could only agree with
  itself.

Cost is one `eth_getLogs` per sample, 24 a day at the default, and a sample holds at most 20,000
logs. Only contract event tables are compared, without `block_timestamp`, since no headers are
fetched.

## Entity state gauge

`/metrics` carries `nuthatch_entity_state_bytes{nest,entity}`, DBSP's used-memory figure for each
authored incremental entity's circuit (#1834). It is sampled on the circuit's own thread after the
entity changes, at most once every `NUTHATCH_ENTITY_STATE_SAMPLE_SECS` (default 60; `0` turns it
off). An idle circuit is never sampled. Measured on the ThinkPad, one sample costs 0.16 ms for 82
groups and 3.26 ms for 510,692 groups holding 1.37 GB.

## Operations

- The release gate runs every production nest, each against its own copy, query set and the
  budget its unit runs under, and posts `release-gate/<nest>`. A unit that sets no budget variables
  is gated on the defaults (#1794, #1855).
- The gate's peak RSS is the kernel's high-water mark at each server's stop on Linux, not a
  half-second sample, which had missed a spike by about 180 MiB (#1833).

## Compatibility and upgrade

Replace the binary and restart. There is no storage migration or re-index.
