Nuthatch 4.2.1 rebuilds the built-in admin page so that an operator can see the whole of a running
nest from a browser. Nothing in indexing, storage or query answers changes.

## The admin page

`/_admin/` grows from four tabs to eight. It is still one file embedded in the binary, makes no
external request, and writes nothing.

- **Overview**: readiness and stall state, tip, indexed and sealed heights, backfill progress, rows,
  disk, memory, CPU, RPC and SQL counters, with rates over the last minute.
- **Tables**: grouped by contract. Each table shows its columns, sealed rows and bytes, newest rows
  and its segments.
- **SQL**: an editor with a bind check, history and saved queries kept in the browser, the nest's
  named queries, provenance for each answer, and CSV or JSON export.
- **Entities**: authored incremental entities with how far each has applied, and their rows.
- **Storage**: the sealed catalogue per table, including files it names that are not on disk.
- **RPC and ingest**: requests, failures, retries and latency per endpoint, calls per method, and
  SQL refusals by reason.
- **Config**: the limits the process runs with, its contracts, and the authored files as text.
- **Raw**: the plain endpoint responses.

The page now fetches relative to its own path. The previous one fetched from the site root, so a nest
served behind a proxy path prefix showed the data of whichever nest answered at the proxy's root.

It lays out for a phone as well as a desktop.

## Admin API

Two routes, gated exactly like the page (absent under `--no-admin`, token required off localhost):

- `GET /_admin/config` returns the text of `nuthatch.toml`, `semantic.toml`, `entities.toml`,
  `queries.toml` and `views/*.sql`, and the limits the process runs with. Every URL is cut to its
  scheme and host, and the value of any `secret`, `token`, `password` or `api_key` key is withheld.
- `GET /_admin/storage` returns segment count, rows, bytes and block range per table, and with
  `?table=` that table's segments, newest first.

## Compatibility and upgrade

Replace the binary and restart. There is no storage migration, configuration change or re-index.
