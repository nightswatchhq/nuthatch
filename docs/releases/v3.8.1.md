Fixes a delay encountered while backfilling Edge & Node's QoS oracle with 3.8.0. Historical postings
repeatedly named the empty UnixFS file, but the IPFS fetcher rejected its empty HTTP response before
checking the CID. The resolver then retried those immutable bytes ten times, spending about half an
hour in each affected direct-seal window. The production backfill reached only 22% after ten hours.

## Empty files are checked against their CID

CID-addressed empty and whitespace-only bodies now reach the existing proof check (#1397). A
response still has to match its requested CID. An empty response for a nonempty document cannot
pass, and an unaddressed empty URL remains an error.

For a declaration with typed rows, a proven empty file is then refused as invalid JSON immediately.
It contributes no rows and is counted as a refusal, without retrying its download. This does not
repair malformed source documents or turn them into zero-valued observations.

## Upgrade

Replace the binary and restart. No configuration, flags, schema, storage identity or sealed
segments change. An interrupted direct-seal backfill resumes from its saved watermark. Documents
already given up on in sealed history are not revisited by upgrading; inspect the nest's coverage
before making completeness claims.

## Verification

The regression failed against 3.8.0's guard with `empty body`. The focused suites pass 48 tests,
including an HTTP 204 resolver test that asserts one request, one typed-row refusal and no stored
rows. Additional tests cover whitespace content, a mismatched CID, gateway failover, and an
unaddressed empty URL.
