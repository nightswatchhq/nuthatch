Nuthatch 3.10.0 is a small release with one change that matters when upgrading. The GraphQL routes
leave the default build and now need a build with `--features graph`. A live mount of a second name
onto a dataset that is already mounted now works. For a deployment that serves no GraphQL clients it
is a binary swap and a restart.

## Compatibility and upgrade

**The GraphQL routes need a `graph` build (#1440).** `/graphql`, `/subgraphs/id/{id}` and
`/subgraphs/name/…` are registered only in a binary built with `--features graph`. The published
binary and the container images are not built with it, so from this release they answer those routes
with 404. The porting commands, `init --from-subgraph`, `port-emit` and `graph-validate`, stay in the
default build. A deployment that serves GraphQL clients should build with `--features graph` before
it upgrades.

No CLI flag, `nuthatch.toml` key or metric was removed or renamed, and the NID and data identity are
computed as before.

## Two mounts of one dataset, live (#1475)

`POST /_admin/nests` with a second name at a NID another mount already serves failed with
`Database already open. Cannot acquire lock.`, although the same pair worked when both were in
`mounts.toml` at boot. The second mount now shares the first one's open store, as boot does. It is
not indexed twice and not charged against the cursor's budget a second time, and it gets its own
mount record's SQL surface.

Unmounting either mount leaves the other serving and following the tip. Before, unmounting the one
the dataset was indexed under stopped the cursor for both. The store is released when the last mount
of the dataset goes.
