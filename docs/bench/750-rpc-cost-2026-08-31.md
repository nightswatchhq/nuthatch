# #750: what a running nest costs, re-measured

Read live from the Lodestar VPS on **2026-08-31 06:20 UTC**. Window: all six nests restarted
**2026-08-29 18:19:56 UTC**, so counters cover **1.50 days**. All on `nuthatch-3.0.1`.

Stated with its window because every figure here is a rate, and the August audit's headline number
has been quoted since without one.

## The August number was right, and it is no longer the number

The audit recorded **~122,000 RPC per HTTP request served**. It is now **659**. That is a 185x
improvement and **almost none of it is ours**:

| | Aug 2026 audit | 2026-08-31 |
| --- | ---: | ---: |
| RPC per nest per day | ~410,000 | ~505,000 |
| HTTP served per day, all nests | ~13.5 | **3,828** |
| ratio | 122,000 : 1 | 659 : 1 |

**The RPC cost per nest did not fall. Demand arrived.** The ratio was catastrophic because nobody was
querying, and it is respectable now because somebody is. Both readings describe the same product.

**That is the durable finding**: tip-following cost is a constant, independent of demand. A nest that
nobody reads costs the same as one under load. `docs/` already carries the standing note that a parked
nest burns real money; this puts a current number on it.

The clean contrast is on the same box. **`graph-staking-legacy-history` (8103) serves 162 requests for
0 RPC calls** - a read-only nest over sealed history, paying nothing to exist. Every RPC call in the
table above buys tip-following, not serving.

## Where the calls go

`graph-staking-nest`, over the same window:

| method | calls | share |
| --- | ---: | ---: |
| `eth_getBlockByNumber` | 532,646 | **59.9%** |
| `eth_blockNumber` | 178,945 | 20.1% |
| `eth_getLogs` | 178,085 | 20.0% |

**`eth_getBlockByNumber` is 60% of the bill**, and it is the block-timestamp fetch - one header round
trip per block carrying rows.

### The obvious lever is closed

`block_timestamps = false` would remove that 60%. It is not available here:

- **Three of `graph-allocations-nest`'s eight views use `block_timestamp`** - 12 references across
  `40-lodestar-allocations.sql`, `60-lodestar-disputes.sql` and `70-lodestar-escrow.sql`.
- Flipping it is a **breaking schema change** (RFC-0029 §6b): it adds or removes a column on every
  table and changes the bytes of every sealed segment, so existing segments cannot be reused.
  `config.rs` refuses to start on a mismatch. It means a full re-index, not a config edit.

So the 60% is structural for any nest whose views need timestamps. Recorded rather than solved.

## Rate limiting, which the audit did not see

429s in a single hour, by unit:

| unit | endpoint class | 429s/hour |
| --- | --- | ---: |
| `nuthatch` | shared | **44** |
| `nuthatch-gns` | shared | **43** |
| `nuthatch-ds-upstream` | shared | **38** |
| `nuthatch-dips` | shared | 1 |
| `horizon-nest` | paid (Alchemy) | **0** |
| `entity-soak` | - | **0** |

Every unit on the shared endpoint is being rate-limited about **40 times an hour**; the one on a paid
endpoint is not. Each 429 is retried, so the refusals **inflate** the RPC counts above rather than
capping them. The three nests are paying for the same block twice.

This is a cost argument for the paid endpoint rather than only an etiquette one, and it is the
measurement the endpoint decision should rest on.

## Corrections to #750

Four of its findings have moved:

1. **The endpoints are no longer `arb1.arbitrum.io`.** They are `petko-rpc.infradao.tech` and, for
   `horizon-nest`, Alchemy. The free-public-endpoint problem the audit named is already gone.
2. **`doudouchain-v2-nest` is gone** from :8100. The board call the audit asked for is moot.
3. **`nuthatch-ds-upstream` does expose `/metrics`** - at `/horizon/metrics`. A multi-nest runtime
   carries metrics on each nest's base path and 404s at the root, by design. The audit read the root.
4. **There are three dead Caddy routes, not two.** `verify.*`→8787 and `mcp.*`→8788, plus
   `/livepeer/*`→8097 inside the live `nuthatch.*` host.

And one that stands: **the three Lodestar nests are reachable**, by path under
`nuthatch.89.167.109.4.sslip.io` behind basic auth, not unproxied as the audit suspected.

## What changed on the box

- **`nuthatch-ds-upstream` upgraded 2.5.0 → 3.0.1.** Ready in 4 s; verified by reading
  `/proc/<pid>/exe`, not by trusting the unit file. Unit and `mounts.toml` backed up first.
- **The two dead host blocks removed** (`verify.*`, `mcp.*`). Both now resolve to no route.
- **`/livepeer/*` returns an explicit 410** rather than being deleted. Deleting it was the obvious
  move and would have been a defect: that host ends in a catch-all `handle` proxying to 8095, so
  removing the route would have served **graph-staking-nest's data under a livepeer path** - silently
  wrong answers in place of a clean failure.

Caddyfile backed up and `caddy validate`d before reload; every live nest path re-checked after.
